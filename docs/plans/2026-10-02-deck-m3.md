## Destination

A session that runs in a deckd PTY can be unblocked from the browser, safely. Every permission request
gets a tier from the M3 classifier (`hub/server/approvals/`): the layered `tiers.json` over shipped
defaults that carry every adopted review change, with floors that no entry can lower and a corpus test
that holds every command quoted in the review. Answers are option keys typed into the PTY by deckd only
when the screen still shows the prompt the server parsed and no one typed in the last second; the deck
proves each answer by the prompt leaving the screen or a matching hook, else shows "did not land", and
never retries on its own. The drawer answers Allow, Deny, Reply and option picks, batches Safe requests
only, and puts Destructive allows behind a checkbox whose label comes from the entry's template; Home
cards, the palette and the Focus PromptBar answer within the tier rules, and the PromptBar offers option
2 only under the Q7 rule. A Safe popup offers "Allow once" only for a single request whose whole command
it shows. Safe approvals (browser or terminal) count toward "Make it a rule?" at the configured
threshold; accepted, hand-added and revoked rules are written to `<repo>/.claude/settings.local.json`
preserving every other key and the order, with backups, and rules the deck did not write show as "added
by hand". The Focus Changes tab shows the diff against the review baseline, and Settings has the
Approval rules section. Automated suites cover exit criteria 1, 2, 3 and 6 of `docs/deck/12-milestones.md`
section 5; criteria 4 and 5 need the owner and are recorded as pending in `docs/deck/m3-exit.md`.

  `hub/package.json` and `hub/package-lock.json`, pinned to exact versions. M3 adds no dependency.

- Hub tests run with a short TMPDIR: `mkdir -p /tmp/hx && TMPDIR=/tmp/hx npm --prefix hub test`.
  Unix socket paths are limited to about 108 bytes. Tests use temporary HOME, XDG and runtime
  directories, never the owner's live settings, shell profile, `settings.local.json` files or services.
- Never run real Claude Code in a test. Use `hub/test/fake-claude/fake-claude.mjs` (through
  `hub/test/helpers/fake-bin.mjs`), `hub/test/integration/stubs/claude` and the captured 2.1.282

  no test ever runs the owner's `$SHELL -l -i`.
- The web server binds IPv4 loopback only. Every new `/api/*` route and the WebSocket keep the
  token, Host and Origin checks of `docs/deck/05-api.md` section 1 and `docs/deck/08-security.md`
  sections 4.1 and 4.2. New routes are written in the shapes `route === '<literal>'` or
  `s[1] === '<resource>' && s.length === N && s[3] === '<action>'` (or `s[1] === '<resource>' && s.length === N`
  for a route with no action segment) inside the matching method block of `hub/server/http/api.mjs`,
  because `routerTable()` in `hub/test/e2e/security.spec.mjs` reads those shapes to prove every route
  refuses a missing or wrong token. The new DELETE route lives in its own `if (method === 'DELETE')`
  block, which Task 17 teaches `routerTable()` to read.
- `apiVersion` stays 1. Every API change in M3 is additive (`docs/deck/05-api.md` section 8). The deckd
  protocol stays `proto` 2; the guarded write is an additive `write` field announced by a `features`
  list in `hello` (Task 4).
- Answers reach the PTY only through `hub/server/approvals/deliver.mjs` (Task 10), as a deckd `write`

  batch, never from a popup and never by a keyboard shortcut. The server never logs input bytes,

  `xdg-open`) are started with an argv array, never a shell string, with a timeout, and without the
  deck token in their environment (`docs/deck/08-security.md` section 4.8). Every git call in M3 goes
  through the read-only helper of Task 11 with the 4.8 flags.

  `hub/web/src/components/StatusPill.jsx`, as the M1 and M2 screens do; `hub/web/src/i18n/en.js` keeps
