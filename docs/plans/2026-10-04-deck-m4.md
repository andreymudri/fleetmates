## Destination

Meetings work from the deck over TurbidAssist's `scribed` socket, with scribed and TurbidAssist unchanged. The server holds the complete scribed client and the recorder machine of state-machines 6
(2 s `status` poll, start with a tag from `config.yaml`, a `stop` that may take minutes, other clients' recordings,
subscription with reconnect and gap fill, scribed health with backoff), follows each meeting's post-processing from
`session.json` and finds its synthesized note on disk, keeps only deck facts in SQLite (meeting rows, pins,
dismissals) and never persists transcript, ask or pin text for a confidential tag, nor transcript text for any tag.
The browser shows the Meetings list, detail and search, the live view with transcript, pins and the transcript-only
ask, the recording bar on every screen, the scribed degraded card and Home Calm "Last meeting"; "Start scribed" uses
the decided `systemd-run` command; quiet mode follows the full recorder machine. Automated suites cover exit criteria
2 to 4 of `docs/deck/12-milestones.md` section 6, and the contract tests of criterion 1 run on the hand-copied
`d4ffb9d` fixtures; criterion 1 stays owner-pending until TurbidAssist has an exporter, and criterion 5 needs the
owner; both are recorded as pending in `docs/deck/m4-exit.md`.

## Global Constraints

- Base branch: `feat/deck`, after the M3 run (`run/deck-m3`) has merged into it with its Task 18 (hub version 0.3.0,
  `BUILD` `'m3'`, `docs/deck/m3-exit.md`). If `feat/deck` lacks any of those when the run starts, stop and ask the
  owner. Run branches start from `feat/deck` and the gate compares against it.
- Root package runtime and development dependencies remain zero. Hub dependencies stay in `hub/package.json` and
  `hub/package-lock.json`, pinned to exact versions. M4 adds no dependency without the owner's approval; in particular
  `config.yaml` is read by the subset reader of Task 4, not by the `yaml` package.
- Node >= 24.2.0. Use built-in `node:sqlite`, `node:net`, `node:http` and ESM `.mjs` for the server.
- Hub tests run with a short TMPDIR: `mkdir -p /tmp/hx && TMPDIR=/tmp/hx npm --prefix hub test`. Unix socket paths
  are limited to about 108 bytes; fake scribed sockets live in `makeRuntimeDir()` directories
  (`hub/test/helpers/runtime-dir.mjs`).
- Tests use temporary HOME, XDG, runtime, `session_dir`, vault and `config.yaml` trees, never the owner's TurbidAssist
  checkout, `config.yaml`, `session_dir`, vault, scribed socket, live settings or services.
- Never run real scribed, `scribe`, `postmeet`, `systemd-run`, `systemctl`, `notify-send`, `makoctl`, `pw-play` or
  `xdg-open` in a test: each is a shim first on a temporary `PATH` that logs its argv. The fake scribed
  (`hub/test/fakes/fake-scribed.mjs`, Task 2) runs inside the test process.
- Never run real Claude Code in a test (use `hub/test/fake-claude/fake-claude.mjs` through
  `hub/test/helpers/fake-bin.mjs`). Never run a bare `node --test` at the repo root: its glob reaches
  `hub/test/capture/capture-cc.mjs`. Any test that starts deckd passes `startDeckd({ loginEnv })`.
- M4 does not change `hub/deckd/` or the deckd protocol. Never restart, stop or reconfigure the owner's dogfood deck
  (`~/deck-dogfood`), its deckd, its web server or any of the owner's systemd user units.
- The fleet never reads into, edits or runs anything in TurbidAssist. A future exporter and its runs are the
  owner's.
- The web server binds IPv4 loopback only. Every new `/api/*` route keeps the token, Host and Origin checks of
  `docs/deck/05-api.md` section 1 and `docs/deck/08-security.md` 4.1 and 4.2, and is written inside the matching
  method block of `hub/server/http/api.mjs` in one of the shapes `route === '<literal>'`,
  `s[1] === '<resource>' && s.length === N`, `s[1] === '<resource>' && s.length === N && s[3] === '<action>'` or
  `s[1] === '<resource>' && s.length === N && s[3] === '<word>' && s[5] === '<action>'`, because `routerTable()` in
  `hub/test/e2e/security.spec.mjs` reads those shapes (Task 17 teaches it the last one). Literal routes
  (`meetings/search`, `meetings/start`, `meetings/stop`) are tested before the `s[1] === 'meetings'` parameter routes.
- `apiVersion` stays 1 and every API change is additive (05-api section 8). New error codes map to statuses in
  `codeStatus` of `api.mjs`: `unknown_tag` 422, `scribed_refused` 409 (scribed's message verbatim in `details.text`),
  `scribed_unavailable` 503 with `retryable: true`, `not_recording` 409, `ask_in_progress` 409,
  `dependency_start_failed` 502.
- Meeting content rules (06-storage 10.1, 08-security 4.12): no column, event, log line, notification, audit row or
  browser storage holds transcript text, ask text or answer text for any meeting, or pin labels for a confidential
  one. `meeting.transcript`, `meeting.recovered`, `ask.delta`, `ask.done` and `ask.error` are ephemeral (never
  appended to `events`) and carry `ephemeral: true`. Logs record event types, ids, lengths and error codes only.
  Notification bodies never contain meeting text.
- Files under `session_dir` and the vault are read with the realpath of the target inside the realpath of its root,
  `O_NOFOLLOW`, a regular-file check and a size cap; the deck never writes to `session_dir`, `config.yaml`, the vault
  or `Tasks/Inbox.md`.
- Child processes (`systemd-run`, `xdg-open`, `notify-send`, `pw-play`) are started with an argv array, never a shell
  string built from data, with a timeout, and without the deck token in their environment (08-security 4.8).
- Untrusted text (transcript lines, note sections, action items, tags, scribed messages, ask answers, file names) is
  rendered as text, never as HTML. Markdown goes through `renderMarkdown` of
  `hub/web/src/screens/team-run/PlanDrawer.jsx` (`markdown-it` with `html: false`). No `dangerouslySetInnerHTML`.
  Meeting content nodes carry `lang="pt-BR"`.

  `hub/web/src/components/StatusPill.jsx`; `hub/web/src/i18n/en.js` keeps the shell keys. Copy strings come from the

  `hub/web/src/styles/meeting-live.css` and imports both once from `hub/web/src/main.jsx`; other tasks extend the
  stylesheet they own.
- Each new test must fail for a deliberate mutation of the behaviour it claims to cover, then pass after restoration.
  Every test step below names its mutation. Record the mutation and the command in the task result. Where a task
  changes behaviour an existing test pins, update only the assertions that pin the old behaviour, and say which.
- Style: single quotes, two-space indentation, no semicolons, JSDoc for public JS exports.
- Commit messages: one English commitlint line with scope `deck`; no tool attribution of any kind (no
  `Co-Authored-By`, session links or "Generated with" lines) in commits, PR bodies or tags.
- Public files use placeholders such as `/home/you`, tags `pessoal`, `client-a`, `client-b`, `acme`, never real names,
  usernames, emails, client names or home paths. Docs in `docs/deck/` are English plain prose without the em dash
  character. The character U+2014 appears only where the TurbidAssist format demands it (note file names written by
  the fixture helper of Task 6).
- Do not edit `fleetmates.gate.json`, any plan in `docs/plans/`, or `.fleetmates/` to make a check pass. Do not
  publish, tag or push.
