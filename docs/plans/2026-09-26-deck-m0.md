# fleetmates deck M0 (Spike) Implementation Plan

Source: `docs/deck/12-milestones.md` section 2 (scope, exit criteria) and section 10.1 (task
breakdown), refined where the handoff contradicts itself or the plan format. Every deviation from
10.1 is listed under "Deviations from the handoff" and must be carried into the spike report.

## Destination

The M0 exit criteria in `docs/deck/12-milestones.md` section 2 are met or explicitly handed to the
owner: a real Claude Code 2.1.282 session spawned by deckd renders and accepts input through
node-pty and xterm.js, two input sources share one PTY under "last keystroke wins" with a recorded
`lastInputFrom`, the first real hook and screen fixture sets are committed and parsed, the scribed
client decodes the hand-copied protocol fixtures, a killed spike web server reattaches without
losing the PTY, keystroke echo p95 is measured, and `docs/deck/spikes/m0.md` answers SM-O1, SM-O6,
SM-O12, TEST-O2 and OPS-O2 with a chosen default each. Criteria 1 (side-by-side kitty vs Chromium
screenshots) and the real-scribed half of criterion 6 are manual owner checks; the report lists
them with the exact steps, and the run is landable without them.

## Global Constraints

- All deck code lives under `hub/`; the root plugin (`package.json`, `scripts/`, `skills/`, `agents/`, `hooks/`, `tests/`) is not modified by any task.
- The root `package.json` keeps zero dependencies; every dependency goes in `hub/package.json`.
- Node: `"engines": { "node": ">=24" }` in `hub/package.json`. Do NOT add `hub/.node-version` or `.tool-versions`: mise would then demand a Node that is not installed and break the `npm` shim.
- Style as in the root: ESM `.mjs`, no semicolons, single quotes, 2-space indent, JSDoc on exported functions.
- Tests: `node:test` + `node:assert/strict`, run by `npm --prefix hub test` (`node --test "test/**/*.test.mjs"`). Every test that touches sockets creates its own temp `XDG_RUNTIME_DIR` via `hub/test/helpers/runtime-dir.mjs` and never uses the real one.
- Tests never start the real `claude`. They use the fake from `hub/test/fake-claude/` (or, for Task 2 only, the stub described there) put first on `PATH`.
- Pinned Claude Code version for fixtures: `2.1.282` (the output of `claude --version` on the owner's machine at planning time). Fixture directories are named `2.1.282`.
- scribed fixture directory: `hub/test/fixtures/scribed/d4ffb9d/` (TurbidAssist commit at planning time).
- deckd socket path: `$XDG_RUNTIME_DIR/fleetmates-deck/deckd.sock`, dir 0700, socket 0600; protocol exactly as `docs/deck/05-api.md` section 5 (proto 1, JSON lines, base64 byte payloads).
- In a worktree, run `npm ci --prefix hub` before anything else in `hub/` (Task 1 creates the lockfile).
- Commit messages: single-line, commitlint style, English, scope `deck` (e.g. `feat(deck): ...`). No `Co-Authored-By`, no session links, no tool attribution.
- Docs follow `docs/deck/README.md` conventions: English, plain prose, no em dash character, placeholders (`/home/you`) for personal paths.
- Environment walls, the same three every time: (1) no `sudo`, `pkexec` or anything that asks for a password; (2) no interactive 2FA or login prompts, the shell cannot answer them; (3) no stdin prompts (`read`, confirmation dialogs). If a step needs one of these, stop and report `blocked`, naming the exact command and what it asked for.
- Every claim in a result or doc about what code does must be backed by a command you ran in your worktree; quote the command and its relevant output. A claim you could not run is labelled "not run".

## Deviations from the handoff

- `hub/package.json` is created in M0 (Task 1), not M1 T1: node-pty, `@xterm/headless` and `ws` are needed now. M1 T1 must treat it as Modify.
- Screen parsers live in `hub/server/screen/`, not `hub/deckd/screen/`: `05-api.md` section 5.4 puts parsing in the web server and keeps deckd boring. deckd keeps only the headless model (`hub/deckd/screen-model.mjs`). This answers API-O5 for M0.
- The capture run is its own task (Task 4), separate from writing the capture script (Task 3), so the fake and the capture tool can be built before a real Claude Code session is spent.
- scribed fixtures are hand-copied from `TurbidAssist/tests/realtime/test_protocol.py`; the T0 exporter is not built (optional until M4).
- `fm` in M0 has `claude` and `attach` only; `ls`, detach escape and the no-deckd fallback are M2 T2.

## Not Yet Specified

- Does the owner accept a nested Claude Code session started by a teammate as the capture operator, or must `capture-cc.mjs` always be run by the owner by hand? Task 4 tries it unattended and reports `blocked` if the nested session refuses to start.

## Out of Scope

- SQLite, hook ingest, the real `deck-hook`, any product screen, auth beyond the loopback bind, packaging, systemd units, CI job for `hub/` — `12-milestones.md` section 2 puts all of these in M1 or later.
- TurbidAssist protocol fixture exporter (T0) — optional until M4, and it lives in another repo that a worktree of this repo cannot write.
- `claude -p` Ask fixtures and transcript fixtures — used from M5 and M1 respectively; capturing them now spends subscription time on data nothing in M0 reads.

- [ ] **Step 1:** `protocol.mjs`: `encode(obj)` returns `JSON.stringify(obj) + '\n'`; `createLineDecoder(onMessage, onError)` returns a `(chunk) => void` that buffers, splits on `\n`, parses each non-empty line and calls `onError({ code: 'bad_json' })` on parse failure without closing. Constants `PROTO = 1`, `OUTPUT_QUEUE_CAP = 8 * 1024 * 1024`.
- [ ] **Step 2:** `ring.mjs`: a scrollback ring capped at 5,000 lines or 2 MiB, whichever is smaller (`03-architecture.md` 2.1). API `push(buf)`, `snapshot()` returns a `Buffer` of the retained bytes.
- [ ] **Step 3:** `screen-model.mjs`: wraps `@xterm/headless` `Terminal` (`allowProposedApi: true`, scrollback 0). API `write(buf)`, `resize(cols, rows)`, `lines()` returns visible rows as trimmed-right strings, `cursor()` returns `{ x, y }`, `rev` increments on every change. `watch(onScreen)` emits `{ rev, lines, cursor, changedRows }` throttled to at most 4 per second and only when rows changed (`05-api.md` 5.4).
- [ ] **Step 4:** `pty-host.mjs`: one class per PTY holding the `node-pty` process, the ring, the screen model, attached clients, `lastInputFrom`, `lastInputAt`. Spawn adds `FLEETMATES_DECK_PTY=<ptyId>` to env; ptyId is `pty_` + 8 random hex chars. Refuse any `argv[0]` whose basename is not `claude` with error code `spawn_refused`. `kill` sends SIGTERM to the process group, SIGKILL after `graceMs`. Resize follows the source of the most recent input, at most once per second (SM-O12 default, `interaction/state-machines.md` 3.5).
- [ ] **Step 5:** `main.mjs`: creates `$XDG_RUNTIME_DIR/fleetmates-deck/` with mode 0700, listens on `deckd.sock`, chmods it 0600, removes a stale socket file only after a failed connect to it. Implements every op in `05-api.md` 5.2 (`hello`, `spawn`, `list`, `exits`, `attach`, `detach`, `screen`, `watchScreen`, `write`, `resize`, `kill`, `ping`) and every event in 5.3. `write` stamps `source` and emits `input` events carrying the byte count, never the content. Per-client output queue cap of 8 MiB, then `dropped`. Exits cleanly on SIGTERM, killing all PTYs. Runnable as `node hub/deckd/main.mjs`. `SO_PEERCRED` is not available from Node without a native addon: rely on the 0600 socket mode and write that in a comment.
- [ ] **Step 6:** `hub/test/integration/stubs/claude`: an executable Node script (`#!/usr/bin/env node`) that sets raw mode when stdin is a TTY, prints `READY\r\n`, echoes every input byte, and prints `SIZE <cols>x<rows>\r\n` on SIGWINCH. It exists only so deckd tests do not depend on Task 3.
- [ ] **Step 7:** `deckd-protocol.test.mjs`: the decoder handles split chunks, several lines per chunk, and bad JSON without closing.
- [ ] **Step 8:** `deckd.test.mjs` starts `main.mjs` as a child with a temp runtime dir and the stub first on `PATH`, then asserts: socket mode 0600 and dir 0700; `hello` answers `proto: 1` and a `bootId`; `spawn` of `['claude']` returns a ptyId and a `spawned` event; `spawn` of `['bash']` fails with `spawn_refused`; `write` with `source: { kind: 'terminal', name: 'kitty' }` reaches the stub (echo in `output`) and `list` shows `lastInputFrom.kind === 'terminal'`; a following browser write flips it to `browser`; `screen` returns the `READY` row; `resize` from the last input source changes the size the stub reports; `kill` produces an `exit` event and `exits { since }` returns it; a client that stops reading receives `dropped` after the cap (use a small cap via env `DECKD_OUTPUT_QUEUE_CAP` for the test).
